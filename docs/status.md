# Lathe — Current Status

This page tracks the features implemented on `main`.
For the setup that works with the published plugins, start with the [README](../README.md).
For planned work, see the [roadmap](roadmap.md) and [design index](design-index.md).

## Release State

Lathe is published to Maven Central.
Maven and Gradle install the server through a build plugin, and the OpenJDK integration reads the output of a JDK build.
The [editor support table](#editor-support) lists the available clients.
Coding agents use the same analysis through the [MCP tools](#ai-agent-integration-mcp).
Maintainers publish signed artifacts from release tags.
[Release procedure](../RELEASING.md)

## LSP Capability Matrix

Navigation, completion, references, rename, diagnostics, code actions, and project formatting are implemented.
Inlay hints and on-type formatting are deferred.
Selection ranges and code lenses are unimplemented.

A new name that collides with an existing declaration is refused with the reason: a member of the same kind the owner declares or inherits (a method only with the same erased parameters), a sibling type, or a variable in scope. A rename that would change what a name means is refused too, naming the file and line, in every module that sees the symbol: a use the new name would capture (a field a renamed parameter would shadow, a call the renamed overload would pick up, a subclass method that would then override it) or a renamed use that would then refer to something else; uses that only reflection, strings or configuration make are not checked. | `outline` | Lists declarations in a file with their locations and signatures. |

| `verify_change` | Recompiles changed files and their callers and reports the errors that remain. |
| `rename_symbol` | Renames the symbol and updates references on disk. |

Each session writes its tool log under `~/.cache/lathe/logs/`.

## Implemented Architecture

- JSON schemas in `lathe-core` define compiler params and workspace state.
- `WorkspaceSession`, confined to the single server worker thread (`lathe-worker`), owns mutable workspace state and client publication.
- One module worker owns each javac-backed `SourceAnalysisSession`.
- LSP4J threads capture immutable inputs and enqueue work.
- `DocumentRegistry` owns open-document generations and stale-result validation.
- `DiagnosticPublisher` owns diagnostic publication and semantic-token refresh requests.
- `ReferenceCandidateIndex` maps Java identifier tokens to source files for reference search; each write pass syncs it with files changed on disk outside the editor.
- `CompilationAdmission` bounds concurrent javac tasks across reference search and interactive compilation.
- Module sessions (their jar indexes) are released after 5 idle minutes, and earlier when the JVM reports the old generation above 70% after a collection; `verify_change` checks files without opening them ([design](done/lathe-memory-pressure.md)).
- `WorkspaceTypeIndex` merges dependency/JDK shards with reactor output entries for type discovery.
- `WorkspaceTypeIndex` also provides immutable direct-supertype, direct-subtype, and transitive-subtype queries.
- External sources use standard read-only `file://` files under the Lathe cache.

See [lathe-server-data-flow-recipe.md](done/lathe-server-data-flow-recipe.md) for the threading and data-flow recipe.
